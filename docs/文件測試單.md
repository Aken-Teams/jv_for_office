# JVision for Office · 文件測試單

以**產出的文件**為單位，不是以工具為單位。每一種文件 5~6 題，從最單純的一句話到最刁鑽的情境，
一題一題跑完就知道這類文件做得如何。

> **怎麼用。** 一次一題，每題都從**空白文件**開始（除非題目說「接續上一題」）。
> 每題下面的「**要看什麼**」是這題的及格線——做得出來不等於做得好，看的是那幾個點。
>
> 題號後面的記號：`①` 最單純、`⑤` 最刁鑽。前面幾題過了再往後，壞在哪一級就知道極限在哪。

---

# Word

## 一、員工履歷表

### ① 最單純的一句話

```
幫我做一份員工履歷表
```

**要看什麼：** 不問就自己做，還是先問一堆？這種標準表單應該直接做出一份完整的，
而且**是一張大表單**，不是一段一張表。

### ② 指定欄位

```
做一份員工履歷表，要有基本資料（員工編號、姓名、性別、出生日期、身分證字號、
婚姻狀況、兵役狀況、血型）、聯絡資訊（手機、市話、email、戶籍地址、通訊地址、
緊急聯絡人及電話）、學歷、工作經歷、專長與證照。學歷和工作經歷各留三列空白讓人填。
```

**要看什麼：** 所有欄位左緣要對齊、配色要一致（不能前兩段灰後兩段綠）、
學歷和工作經歷要是**表格式區塊**而不是另外插的表。

### ③ 加上照片欄與簽名欄

```
同樣的履歷表，右上角要留 2 吋照片的位置，最下面加「以上資料屬實」的切結文字，
以及填表人簽名、日期、人事主管覆核三個欄位。整份要能印在兩頁內。
```

**要看什麼：** 照片欄會不會把表格撐歪、切結與簽名區是不是跟上面同一張表、
會不會因為塞不下而溢出到第三頁。

### ④ 從既有檔案改

```
（先開一份現成的履歷表）看一下這份表格現在有哪些欄位，幫我補上「語言能力」
和「可到職日」兩個欄位，放在合理的位置，不要動到其他欄位的內容和格式。
```

**要看什麼：** 會不會先讀再改、補的位置合不合理、有沒有把既有內容洗掉。

### ⑤ 中途改規格

```
做一份履歷表……等等，改成應徵用的，不是在職員工用的——所以不要員工編號和到職日，
改成應徵職務、期望待遇、可到職日。前面做的要收掉，不要在後面疊一張新的。
```

**要看什麼：** 能不能**收回**已經做的，而不是在下面再插一張。這是最常壞的地方。

### ⑥ 版面檢查不該亂動

```
（接續上一題）幫我跑一次版面檢查。
```

**要看什麼：** 履歷**不該**被編號成「一、基本資料」，也**不該**每個區塊各佔一頁。
它該檢查的是欄位有沒有空白、對齊整不整齊。

## 二、報價單

### ① 最單純的一句話

```
幫我做一份報價單
```

**要看什麼：** 會不會問公司名稱和品項就卡住。空白的報價單格式也是有用的產出。

### ② 完整品項與計算

```
做一份報價單給「宏達數位科技股份有限公司」，我方是「久億資訊有限公司」。
品項：網站建置 1 式 180000、SEO 優化 6 個月 每月 15000、主機代管 1 年 36000、
教育訓練 2 場 每場 12000。要有小計、5% 營業稅、總計，報價有效期 30 天。
```

**要看什麼：** 數字算對沒有（小計 342000、稅 17100、總計 359100）、
金額欄有沒有千分位、有效期有沒有寫成具體日期。

### ③ 抬頭與條款

```
同一份報價單，上面加公司抬頭（久億資訊有限公司、統編 12345678、
地址 台北市信義區信義路五段 7 號、電話 02-1234-5678），
下面加付款條件（簽約 30%、驗收 60%、保固期滿 10%）和備註三條。
```

**要看什麼：** 抬頭是不是 letterhead 式的版面、付款條件是用表格還是條列、
整份看起來像不像一份對外文件。

### ④ 分階段報價

```
報價單改成分三個方案：基本版 180000、標準版 320000、旗艦版 580000，
每個方案列出包含哪些功能（用打勾表示），讓客戶可以橫向比較。
```

**要看什麼：** 三欄比較表的對齊、打勾符號會不會變成亂碼、哪個方案被凸顯。

### ⑤ 從 Excel 來的資料

```
（先上傳一份品項報價的 Excel）把附件裡的品項做成正式報價單，
金額照附件不要自己改，加上我方抬頭和稅額計算。
```

**要看什麼：** 有沒有真的讀附件、金額有沒有抄錯、品項有沒有漏。

### ⑥ 改版本

```
（接續）客戶殺價了，全部品項打 9 折，但主機代管不打折。重新算稅和總計，
並在備註加一句「本報價為特別優惠價，有效期縮短為 14 天」。
```

**要看什麼：** 會不會全部一起打折（主機代管不該打）、稅額有沒有跟著重算。

## 三、合約書

### ① 最單純的一句話

```
幫我做一份軟體委託開發合約書
```

**要看什麼：** 條款完不完整、條號編得對不對、有沒有把「第一條」寫進標題又另外編號。

### ② 指定條款

```
做一份軟體委託開發合約，要有：合約標的、開發時程與交付、驗收、合約價金與付款、
需求變更、智慧財產權歸屬、保密義務、違約責任、爭議解決、其他約定事項。
金額和日期先留底線空白讓人填。
```

**要看什麼：** 條號連不連續、底線空格的長度一不一致、**條款不該每條各佔一頁**
（那是「有小節才換頁」的門檻在不在的證據）。

### ③ 立合約書人與簽署欄

```
同一份合約，最前面加立合約書人（甲方、乙方各列名稱、統編、代表人、地址、聯絡窗口），
最後面加簽署欄（甲乙方用印、日期），中華民國年月日。
```

**要看什麼：** 甲乙方欄位要並排且等寬、簽署欄要在同一頁不能被切開。

### ④ 付款與時程表格

```
合約裡加兩張表：分期付款表（期別、付款條件、比例、金額）和
交付時程表（階段、交付項目、交付期限），最後一列要有合計 100%。
```

**要看什麼：** 合計列的樣式、兩張表的配色是否一致、欄寬會不會一張寬一張窄。

### ⑤ 改成另一種合約

```
把這份改成「軟體授權使用合約」：不是委託開發，是授權既有產品使用。
授權範圍、授權期間、年費、技術支援、終止條件，智財權全部歸我方。
```

**要看什麼：** 是真的改寫還是在後面加一份新的、原本不適用的條款有沒有拿掉。

### ⑥ 風險提示

```
（接續）幫我看一遍這份合約，站在乙方立場指出哪幾條對我方不利，並說明為什麼。
```

**要看什麼：** 會不會只是摘要條款、有沒有真的指出不利之處、
有沒有適當提醒「這不是法律意見」。

## 四、PRD／產品規劃書

### ① 最單純的一句話

```
幫我做一份個人問卷平台的 PRD
```

**要看什麼：** 章節結構合不合 PRD 的規矩、會不會只寫三段就結束。

### ② 完整結構

```
做一份「個人問卷平台」的 PRD：封面（眉標寫「產品部 · 自助問卷工具」，
要有一句承諾說明為了誰、達成什麼）、目錄、頁首放文件名、頁尾放頁碼，
章節包含產品概述、目標使用者、功能需求、非功能需求、里程碑、風險與對策。
```

**要看什麼：** 目錄前**不能有空白頁**、封面標題要夠大、章節要編號、
大章節要從新的一頁開始（但第一章接在目錄後不該空一頁）。

### ③ 加表格與圖

```
（接續）在目標使用者那章加一張使用者輪廓表（輪廓、典型情境、痛點、關鍵需求，
至少四列），在里程碑那章加一張甘特圖，分三個階段從 2027-01 到 2027-09。
```

**要看什麼：** 表格配色跟文件主色是否同一家、甘特圖**不能是灰的**、
圖下面有沒有圖說。

### ④ 功能清單

```
（接續）功能需求那章補一張功能清單表：編號（F-01 開始）、功能名稱、說明、
優先級（P0/P1/P2）、期程，至少 15 列。表格會跨頁，表頭要重複。
```

**要看什麼：** 跨頁時表頭有沒有重複出現、編號有沒有跳號、欄寬會不會被長說明撐爆。

### ⑤ 長程一次做完

```
幫我做一份完整的「供應商資安評鑑報告」：封面、目錄、頁首頁尾、五個章節
（評鑑範圍、評鑑方法、發現彙總表至少 10 列、風險分析含圖表、改善建議），
最後跑版面檢查。中間不要停下來問我，不確定的地方自己合理假設並在文件裡標註。
```

**要看什麼：** 會不會做到一半就停下來問、十個章節有沒有虎頭蛇尾、
最後的版面檢查有沒有跑。**這題是長程組合能力的照妖鏡。**

### ⑥ 中途按停止

```
幫我做一份 20 頁的完整年度報告，內容越詳細越好。
（送出後數到五，按停止鍵）
```

**要看什麼：** 按下去**立刻**停，不是等它跑完；已經寫進文件的內容留著不自動還原；
如果有確認框跳出來，停止鍵也要能收掉它。

## 五、會議紀錄

### ① 最單純的一句話

```
幫我做一份會議紀錄的格式
```

**要看什麼：** 會議基本資訊、出席、討論事項、決議、待辦追蹤，該有的有沒有。

### ② 從逐字稿整理

```
（貼一段 300 字以上的會議對話逐字稿）把這段逐字稿整理成正式會議紀錄：
會議資訊、出席人員、討論摘要、決議事項、待辦事項（含負責人與期限）。
```

**要看什麼：** 有沒有把口語整理成書面語、決議和討論有沒有分開、
待辦有沒有抓出負責人。

### ③ 待辦追蹤表

```
（接續）把待辦事項改成表格：編號、事項、負責人、期限、狀態，
狀態用「未開始／進行中／已完成」，並在表格下面統計各狀態幾件。
```

**要看什麼：** 統計數字對不對、狀態欄有沒有統一用詞。

### ④ 連續會議

```
做一份第三次專案會議紀錄，要能延續前兩次的待辦——
前兩次有五件未結案的事項，這次要列出來並更新進度。
```

**要看什麼：** 會不會憑空編前兩次的內容、有沒有適當說明資料來源是假設的。

### ⑤ 雙語

```
同一份會議紀錄做成中英對照，重要決議兩種語言都要寫，格式左中右英。
```

**要看什麼：** 左右欄會不會錯位、中英混排的斷行、英文翻譯的品質。

## 六、公文／簽呈

### ① 最單純的一句話

```
幫我做一份簽呈
```

**要看什麼：** 格式對不對（主旨、說明、擬辦）、有沒有用公文體。

### ② 完整簽呈

```
做一份簽呈：簽於資訊處，案由是「申請採購資安弱點掃描工具」，
主旨一段、說明分四點（現況、需求、評估、預算）、擬辦兩點，
最後有層級會簽欄（承辦、單位主管、會辦單位、核決）。
```

**要看什麼：** 公文體的字型和首行縮排、說明的編號格式（一、二、三）、
會簽欄的排列。

### ③ 函稿

```
做一份發文給外部單位的函：受文者是「經濟部工業局」，主旨、說明、正本副本、
發文日期文號、承辦人資訊。用標準公文格式。
```

**要看什麼：** 公文該有的元素齊不齊、格式像不像真的公文。

### ④ 附件清單

```
（接續）這份函有三個附件，在文末加附件清單，並在說明裡適當提及附件編號。
```

**要看什麼：** 附件編號和內文引用是否對應。

### ⑤ 改成另一種文別

```
把這份簽呈改成「報告」，收件者改成總經理，語氣要更精簡，說明壓成三點。
```

**要看什麼：** 是改寫還是另外做一份、公文體有沒有維持。

## 七、分析報告

### ① 最單純的一句話

```
幫我做一份年度營運分析報告
```

**要看什麼：** 有沒有章節結構、有沒有圖表、會不會全部是文字。

### ② 含數據與圖

```
做一份 2026 年度營運分析報告：營收 Q1 2.8 億、Q2 3.1 億、Q3 3.4 億、Q4 4.2 億，
毛利率依序 38%、40%、41%、43%。要有趨勢圖、數據表、三點分析、兩點建議。
```

**要看什麼：** 圖的數字對不對、趨勢圖和數據表是否一致、
分析是不是只是把數字唸一遍。

### ③ 多維度圖表

```
（接續）補一張各產品線佔比的圓餅圖（硬體 45%、軟體 30%、服務 25%），
和一張三年對比的長條圖（2024 9.8 億、2025 11.2 億、2026 13.5 億）。
```

**要看什麼：** 圓餅圖加起來是不是 100%、兩張圖的配色是否同一家、
圖例會不會蓋住資料。

### ④ 執行摘要

```
（接續）在最前面加一頁執行摘要：三個重點、一張關鍵數字表、一句總結。
要讓沒時間看完整份報告的人只看這頁就夠。
```

**要看什麼：** 摘要有沒有真的摘要（不是把章節標題抄一遍）、關鍵數字有沒有挑對。

### ⑤ 從附件做

```
（先上傳一份大的 Excel 月報）把附件的資料做成完整的分析報告：
趨勢、異常、原因推測、建議。資料有幾個月就分析幾個月，不要只看前面幾列。
```

**要看什麼：** 有沒有讀完整份附件（最常見的失敗是只讀前 100 列就下結論）、
異常有沒有抓對。

# Excel

## 八、銷售報表

### ① 最單純的一句話

```
幫我做一張銷售報表
```

**要看什麼：** 會不會問一堆才動手。欄位自己想一組合理的也是好的產出。

### ② 建資料

```
在 A1 開始建一張銷售明細：日期、業務、客戶、產品、單價、數量、小計、區域。
給我 30 列 2026 年的資料，日期要是真的日期格式不是文字，小計用公式算，區域分北中南。
```

**要看什麼：** 日期**要能排序**（是日期不是文字）、小計要是公式不是算好的數字、
資料看起來合不合理。

### ③ 格式與樞紐

```
（接續）把金額欄設成千分位貨幣格式、日期設成 yyyy/mm/dd，
然後在旁邊做一張各區各月的小計表，並把小計大於 10000 的儲存格標成淺紅底。
```

**要看什麼：** 格式會不會把公式變成文字、小計表的數字跟明細對不對得起來。

### ④ 圖表

```
（接續）做一張各區月營收的折線圖，三條線分別是北中南，
圖表放在資料右邊不要蓋住資料，標題和座標軸名稱都要有。
```

**要看什麼：** 資料範圍有沒有抓對、圖例對不對、圖表會不會蓋住儲存格。

### ⑤ 結構變動

```
（接續）在最上面插兩列當標題區，在小計欄右邊插一欄「毛利率」（公式：毛利/小計）。
插完確認原本的公式還指到正確的儲存格。
```

**要看什麼：** 插入列欄之後**既有公式有沒有跑掉**——這是最容易壞又最難發現的。

### ⑥ 大檔

```
（先上傳一份幾千列的 Excel）把附件跟這張工作表逐筆比對，
用客戶+產品當鍵，列出只在其中一邊的、以及兩邊都有但金額不同的。
```

**要看什麼：** 會不會只比前面幾百列就下結論、有沒有誠實說明比對了多少筆。

## 九、預算表

### ① 最單純的一句話

```
幫我做一張部門年度預算表
```

**要看什麼：** 會不會問到底才做。

### ② 完整結構

```
做一張 2027 年度資訊處預算表：費用科目分人事費、設備費、軟體授權費、
教育訓練費、雜支，每個科目分 12 個月，最右邊是年度合計，最下面是月合計和總計。
```

**要看什麼：** 合計用的是公式還是算好的數字、月合計和年合計交叉處對不對得上。

### ③ 實際對預算

```
（接續）在每個月右邊加一欄「實際」，然後加「差異」和「達成率」兩欄，
差異為負的標紅色。
```

**要看什麼：** 欄位一多會不會排版崩掉、達成率有沒有處理分母為零。

### ④ 下拉與驗證

```
（接續）費用科目那欄設下拉選單只能選那五種，金額欄限制不能輸入負數，
輸入錯誤時跳出提示。
```

**要看什麼：** 驗證有沒有真的設上去、提示文字清不清楚。

### ⑤ 多工作表

```
新增一張「彙總」工作表放最前面，用公式從各部門的工作表把總計抓過來，
做成一張跨部門比較表和一張長條圖。
```

**要看什麼：** 跨表公式對不對、改了明細彙總會不會跟著動。

## 十、資料清理與比對

### ① 最單純的一句話

```
幫我清理這份資料
```

**要看什麼：** 會不會直接改。正確的做法是**先報告發現什麼問題，再問要不要改**。

### ② 指定清理項目

```
幫我清理：去掉前後空白、統一全半形、把日期格式不一致的補正、
找出完全重複的列。清理前先告訴我各發現幾個，不要直接動手。
```

**要看什麼：** 有沒有真的先報告、數字對不對、改完有沒有說改了哪些。

### ③ 異常值

```
（接續）找出金額欄的異常值：超過平均值三個標準差的、負數的、空白的，
各列出來並標示在哪一列。
```

**要看什麼：** 統計算對沒有、列號跟畫面對不對得上。

### ④ 交叉比對

```
（先上傳另一份報表）跟附件比對：哪些客戶只在我們這邊有、哪些只在附件有、
哪些兩邊金額不同。差異超過 1000 的特別標出來。
```

**要看什麼：** 比對鍵選得對不對、有沒有漏比、大檔案會不會截斷。

### ⑤ 追公式

```
看一下小計欄的公式是怎麼算出來的，往上追到最源頭的輸入值，把整條鏈列給我，
並指出其中有沒有寫死的常數。
```

**要看什麼：** 追得到幾層、有沒有發現硬編碼。

## 十二、提案簡報

### ① 最單純的一句話

```
幫我做一份提案簡報
```

**要看什麼：** 會不會先問主題。這題問是對的——提案簡報沒有標準格式。

### ② 完整提案

```
做一份「智慧工廠數位轉型」提案簡報給製造業客戶，8 頁：
封面、問題、我們的解法、三階段導入、預期效益（含數字）、
案例、報價摘要、下一步。每頁都要有實際內容不要只有標題。
```

**要看什麼：** 八頁有沒有虎頭蛇尾、每頁是**一次做好**還是先插空白再慢慢補、
文字會不會溢出版面。

### ③ 數據頁

```
（接續）預期效益那頁改成 KPI 版面：產能提升 23%、不良率下降 41%、
人力成本節省 18%、投資回收期 14 個月。四個並排，增減要看得出好壞。
```

**要看什麼：** 數字要大、單位要小、四個要等寬對齊、好壞的顏色對不對。

### ④ 圖解

```
（接續）三階段導入那頁畫成流程圖：盤點評估 → 試點導入 → 全廠擴展，
每階段下面寫時程和關鍵交付。
```

**要看什麼：** 節點文字會不會被框裁掉、箭頭會不會蓋住節點。

### ⑤ 改風格

```
（接續）整份改成深色底的科技風，配色要一致，文字在深色上要讀得清楚。
```

**要看什麼：** 改完有沒有哪一頁的字變成深色配深底、圖表有沒有跟著變。

### ⑥ 中途改主意

```
做五頁產品介紹……等等，改成三頁就好，而且配色換成深色底。
前面做的要收掉，不要在上面疊。
```

**要看什麼：** 能不能**收回**，而不是在後面再加三頁。

## 記錄建議

每題跑完記一行就好：

```
題號 | 一次過 / 要補一句 / 做錯了 | 壞在哪
```

「要補一句」比「做錯了」更值得記——那代表它懂但沒想到，
通常是提示詞或預設值可以解決的；「做錯了」才是能力問題。
